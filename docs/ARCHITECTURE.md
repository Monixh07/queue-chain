# QueueChain architecture

```text
React/Vite (5173)
  ├─ REST requests ───────────────> Express API (4000)
  └─ Socket.IO queue:update <─────┤
                                    ├─ MySQL: private records, sessions, events
                                    └─ Ethers.js signer ──> local Hardhat EVM
                                                               └─ QueueChain.sol
```

The API is the trusted boundary. It validates input, authenticates administrators, stores personal information in MySQL, and calls the deployed contract with a server-side wallet. The browser never receives an administrator private key. The public display endpoints omit names, email, and phone numbers. Socket events contain no private payload; connected screens refetch their appropriately scoped endpoint.

The booking row and queue event include each confirmed transaction hash. Database transactions hold a per-day queue-session lock while assigning a blockchain booking and persisting its returned token. Since MySQL and EVM do not share an atomic commit, a retry with the same idempotency key checks the contract and reconciles an already-confirmed booking into MySQL.

## Important environment variables

See `../.env.example`. The backend expects the contract artifact generated by Hardhat at `blockchain/artifacts/...` and the matching deployed address. The configured private key must belong to an authorized operator on the local chain. Never use development keys on a public network.
